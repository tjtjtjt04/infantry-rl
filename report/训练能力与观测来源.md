## 1. 平衡 —— 靠"不摔"+"逼髋关节出力"

### 1.1 任务

- 任务名：`Infantry-RL-Balance-v0`
- 文件：`tasks\balance\balance_env_cfg.py`
- 观测：**33 维**（10 项）
- 奖励：**15 项**（比 locomotion 少 9 项，**完全没有速度跟踪**）
- 终止：倾角 > **1.2 rad**，或机身高度 < **0.11 m**

### 1.2 奖励构成

| 项 | 权重 | 形式 | 作用 |
|---|---|---|---|
| `alive` | **+0.5** | — | 活着就给分（唯一正奖励来源） |
| `base_height` | **−4** | L1 | 锁住 0.1898 m 的站立高度，不许蹲 |
| **`pitch`** | **−4** | **L1** | **pitch 严格归零** |
| `roll` | −1.5 | L1 | 侧倾约束 |
| `fall_penalty` | **−50** | — | 摔了重罚 |
| **`wheel_torques`** | **−0.05** | L2，**1.0 N·m 死区** | ⭐ 关键设计，见下 |
| `closure_residual` | −1000 | L2 | 五连杆闭环必须闭合 |

### 1.3 ⭐ 关键设计：让「腿」而不是「轮子」负责平衡

```
轮子能瞬间出力调整姿态
   ↓
策略会偷懒：全靠扭轮子平衡
   ↓
后果：轮子打滑 / 超 3.69 N·m 力矩上限 / 上实机就废
   ↓
给 wheel_torques 设 1.0 N·m 死区，超了就罚 −0.05
   ↓
"扭轮子平衡"变贵 → 策略改走髋关节
   ↓
髋关节改变 φ（腿轴角）→ 轮子相对机体前后移动 → 移动重心 → 倒立摆式平衡
```

**为什么髋关节能做到**：两条腿的 φ 变化会把轮子相对机体前后移动。
因为轮子接地、机体在上，这等效于"移动配重" —— 和倒立摆小车同一个原理。
这正是 `infantry-chassis` 里 LQR + VMC 控制器的思路。

### 1.4 现状

- 该任务的 **checkpoint 已删除**（`logs` 目录里已无 balance 记录）
- 但这些奖励项**全部保留在 locomotion 的 24 项里**（`pitch` / `roll` / `base_height` /
  `fall_penalty` / `closure_residual`），所以现在任何一个 locomotion checkpoint 都**自带平衡能力**
- 若要单独训"只站着"的策略 → `TRAIN_MODE = "stand"`

## 1.5 ⚠️ 实测发现：最近两次训练「pitch 惩罚是 0」

在核对训练记录时发现：`logs/.../2026-10-22_01-17-16` 和 `2026-10-22_15-22-23`
两次训练用的配置里，**`pitch` 奖励权重是 `-0.0`（等于 0，pitch 完全不受约束）**。

| 项 | VERSION.md 记录 | 代码当时的值 | 影响 |
|---|---|---|---|
| `pitch` | **−4.0** | **−0.0** | 机身俯仰**完全不罚** → 策略可以随便点头 |
| `roll` | −1.5 | −1.5 | 正常 |
| `base_height` | −4.0 | −4.0 | 正常 |

**原因**：代码里写成了 `weight=-.0`（疑似把 `-4.0` 的 `4` 漏掉），是一个笔误。

**已修复**：`locomotion_env_cfg.py` 中恢复为 `weight=-4.0`。

**这意味着**：`01-17-16`（前进）与 `15-22-23`（原地转）两个策略都是**在没有任何
pitch 约束下**训出来的。它们能跑/能转，但机身的俯仰完全靠隐式约束（`base_height` 的
高度项 + 摔倒终止）间接限制 —— 所以回放里会看到 `pitch deg` 偏大（3~10°）。

> **建议**：修好后重新训练前进/原地转，才能拿到真正"平衡 + 前进"的策略。
> 旧 checkpoint 仍然可用，但不要把它当作"平衡能力合格"的证据。

## 2. 前进 —— 靠三层速度跟踪奖励

### 2.1 模式与指令

`TRAIN_MODE = "straight"`

| 配置 | 值 |
|---|---|
| 速度指令 | `vx ∈ [0.2, 1.2]` m/s |
| 指令保持 | 每 **5~10 s** 换一条 |
| 站立样本 | **10%** 环境指令清零 → 学刹车 |
| 航向目标 | 锁定 **0**（**航向环仍在跑**，专门抵消漂移，但不主动转向） |
| 观测 | **35 维**（比 balance 多 `leg_rates` 4 维） |

### 2.2 三层速度跟踪奖励（各管一个误差区间）

| 项 | 权重 | 形式 | 擅长的误差区间 |
|---|---|---|---|
| `track_lin_vel_x` | **+8.0**（`std=0.15`） | exp 核 | 从"不动"到"动起来" |
| `track_lin_vel_x_l1` | **−2.0** | L1（绝对值） | **恒定梯度**，压最后几 cm/s |
| `track_lin_vel_x_l2` | **−6.0** | L2（平方） | 梯度随误差增长，管大误差 |

**为什么必须三层** —— 看梯度：

| 误差 | exp 梯度 | L1 梯度 | L2 梯度 |
|---|---|---|---|
| 0.50 m/s | ≈ 0（核已饱和） | −2.0 | −3.0 |
| 0.05 m/s | −0.4 | **−2.0** | −0.3 |
| 0.02 m/s | −0.16 | **−2.0** | −0.12 |

`exp(−e²/std²)` 的导数含 `e` 因子，**在 e=0 处梯度为 0**；
在 e 很大时又因核饱和而趋近 0。所以：

- 大误差靠 **L2**（梯度 ∝ e，越远拉得越狠）
- 精度靠 **L1**（梯度恒定，2 cm/s 时仍有 2.0 的拉力）
- 粗定位靠 **exp**（把"大概到速度了"变成大的正奖励）

### 2.3 辅助奖励（防抖 / 防歪）

| 项 | 权重 | 治什么 |
|---|---|---|
| `action_jerk`（二阶差分） | −0.3 | **腿抖**（一阶差分区分不出"快速平滑动作"和"高频抖动"） |
| `joint_acc` | −1e-6 | 关节猛打 |
| **`wheel_axle`** | **−8.0** | **左右轮一前一后**（不许把"腿角不对称"当转向执行器） |
| `heading_error` | −0.6 | 航向漂移 |
| `action_rate` | −4e-3 | 一阶差分（放宽，允许快速响应） |

### 2.4 实测结果

| run | checkpoint | `error_vel_xy` | 真实误差 | `track_lin_vel_x` | 回合长度 |
|---|---|---|---|---|---|
| `2026-10-22_00-28-38` | `model_999` | 0.142 | 0.071 m/s | 5.64 / 6.0 | 995.8 |
| **`2026-10-22_01-17-16`** | **`model_1100`** | **0.122** | **0.061 m/s** | **7.40 / 8.0（92.5%）** | **987.0** |

> `error_vel_xy` 的显示值 = **2 × 真实平均误差**（详见 §5.6）。

## 3. 原地转 —— 训到 500+ 轮还在平台期

### 3.1 模式与指令

`TRAIN_MODE = "yaw_rate"`

| 配置 | 值 | 为什么 |
|---|---|---|
| `vx` | **`[0, 0]`** | 不给前进速度 → 只能原地转 |
| `heading_command` | **`False`** | wz **直接采样** `±2.0 rad/s`，**不走航向环** |
| 指令保持 | **2~4 s** | 换角速度更频繁 |
| `rel_standing_envs` | **`0.0`** | **必须 0**：站立环境会把 `wz` 一起清零，那就没有旋转指令了 |
| 主导奖励 | `track_ang_vel_z`（exp +3.0 / L1 −1.0 / L2 −2.0） | 与前进同样的三层结构，但只跟 yaw |

**`yaw_rate` 与 `spin` 的区别**：

| 模式 | 指令形式 | 学到的能力 |
|---|---|---|
| `yaw_rate` | "以 ω = ±x rad/s 转" | **速度式**转向（匀速转，可连转多圈） |
| `spin` | "转到朝向 ψ*" | **位置式**转向（闭环转到目标角就停） |

### 3.2 实测训练曲线（run `2026-10-22_15-22-23`）

**`error_vel_yaw`（显示值 = 2 × 真实平均误差）**：

| 轮次 | 值 | 说明 |
|---|---|---|
| 0 | 0.062 | 回合还短，指标未累积 |
| **100** | **3.900** | ⚠️ 峰值 —— 策略完全不会转 |
| 300 | 1.793 | 开始学会 |
| 500 | 0.800 | 明显改善 |
| **538** | **0.832** | **平台** |

**`track_ang_vel_z`（满分 3.0）**：`0.015 → 1.41`（约 47%）

**其它**：回合长度 1000（不摔 ✓），`mean_std` 掉到 **0.060**（撞限幅下限 ⚠️）

### 3.3 两个问题

| 现象 | 含义 | 建议 |
|---|---|---|
| `error_vel_yaw` 卡在 0.83 | 真实平均角速度误差 **0.42 rad/s**（指令最大 2.0） | 继续训；500 轮还早 |
| **`mean_std` = 0.060** | **撞到硬限幅下限，探索被压死** | 可能就是平台期的原因 → `entropy_coef` 0.003 → 0.004 |

## 4. 为什么分阶段训，而不是一次全上

| 阶段 | 主导奖励 | 一起训的问题 |
|---|---|---|
| 平衡 | `pitch` / `roll` / `base_height` / `alive` | 速度奖励一开，策略会"为了跑而摔" |
| 前进 | `track_lin_vel_x`（+8.0） | 转向奖励一开，策略会用"歪着走"当转向 |
| 转向 | `track_ang_vel_z`（+3.0） | — |

**一次全上 → 多个主导项互相拉扯 → 掉进"站着不动"或"歪着走"这类局部最优。**
本项目历史上踩过两次：

1. v1.0.2 之前：策略收敛到"站着不动"（因为站着也能拿满 yaw 奖励）
2. v1.0.6 附近：策略学会"左右腿角不对称"来转弯 → 轮子一前一后

**现在的 `full` 模式可以一次训完**，但那是给"已经分项练过、想让一个策略全都会"的场景用的：

| 环境占比 | 指令 | 能力 |
|---|---|---|
| 70% | `vx ±1.2` + 航向随机 | 前进 / 倒车 / 边跑边转 |
| **20%** | `vx = 0`（强制）+ 航向随机 | **原地转** |
| 10% | 全部清零 | 站住 / 刹车 |

## 5. 角速度、姿态角是怎么来的？—— 用了传感器吗？

### 5.1 结论

> **仿真里没有任何传感器模型。**
>
> 没有 IMU 噪声、没有偏置、没有延迟、没有量化误差。
> `base_ang_vel`、姿态角、`base_lin_vel` 全部是 **PhysX 刚体状态的直接读取（真值）**。
>
> 代码验证：全库搜索 `noise=` / `enable_corruption` / `IMU` → **0 处**；
> 观测组也没有 `enable_corruption=True`。

### 5.2 仿真里的真实来源

| 量 | 代码来源 | 底层 | 有噪声吗 |
|---|---|---|---|
| **角速度**（`base_ang_vel`，3 维） | `asset.data.root_ang_vel_b` | PhysX 刚体角速度，转到机体系 | ❌ 真值 |
| **投影重力**（`projected_gravity`，3 维，等价于姿态） | `asset.data.projected_gravity_b` | 由 `root_quat_w` 算出：`Rᵀ·[0,0,−1]` | ❌ 真值 |
| **姿态角 roll/pitch/yaw** | `euler_xyz_from_quat(asset.data.root_quat_w)` | PhysX 刚体四元数 → 欧拉角 | ❌ 真值 |
| **线速度**（`base_lin_vel`，3 维） | `asset.data.root_lin_vel_b` | PhysX 刚体线速度，转到机体系 | ❌ 真值 |
| 关节角 / 轮速 | `asset.data.joint_pos` / `joint_vel` | PhysX 关节状态 | ❌ 真值 |

> 注：姿态角**不是**策略的输入。策略看到的是 `projected_gravity`（等价信息，但更平滑、无万向锁）。
> roll/pitch/yaw 只在**奖励项**（`pitch_abs` / `roll_abs`）和**控制台/回放统计**里用。

### 5.3 上实机后每个量从哪来

| 量 | 实机来源 | 难度 |
|---|---|---|
| **角速度** 3 维 | **IMU 陀螺仪**直接测 | ✅ 直接可用（需标定零偏、滤波） |
| **投影重力** 3 维 | **IMU 加速度计**静止时测重力方向；运动会混入加速度 → 需 EKF 融合陀螺仪 | ⚠️ 需融合 |
| 关节角 4+4 维 | 髋/膝**编码器** | ✅ 直接可用 |
| 轮速 2 维 | 轮**编码器** | ✅ 直接可用 |
| 上一步动作 6 维 | 策略自己输出的，不用传感器 | ✅ |
| `L0`/`φ`/`dL0`/`dφ` 8 维 | 由髋/膝编码器 + 五连杆正解算出 | ✅ 算得出来 |
| **线速度** 3 维 | **没有传感器直接测** → 轮速里程计 + IMU + 卡尔曼融合 | ❌ **最大缺口** |

### 5.4 三个 sim-to-real 缺口

| 缺口 | 说明 | 严重度 |
|---|---|---|
| **① 线速度是"免费真值"** | 仿真里 `base_lin_vel` 直接给。实机要靠里程计+EKF 估计，有噪声和 20~50 ms 延迟 | 🔴 高 |
| **② 完全没有噪声/延迟** | 策略从没见过抖动的 IMU、延迟的编码器。上实机可能抖 | 🟠 中 |
| **③ 姿态角无偏置** | 仿真的 `projected_gravity` 永远准。实机 IMU 有零偏漂移 | 🟠 中 |

**推荐处理顺序**（不要一次全加，否则很难定位问题）：

1. 先用**干净真值**训出能跑的策略（现阶段）
2. 给观测加**噪声**（`ObsTerm(noise=UnoiseCfg(...))`）→ 重训
3. 给观测加**延迟**、给执行器加**力矩/摩擦随机化**（domain randomization）
4. 把 `base_lin_vel` 换成"轮速里程计估计值"再训一次

### 5.5 姿态角在策略里的角色

| 用途 | 具体 |
|---|---|
| 观测 | 不是直接给角度，而是给 `projected_gravity`（3 维） |
| 奖励 | `pitch_abs`（−4，L1）、`roll_abs`（−1.5，L1）、`roll_when_straight_abs`（−2.5，直行时才有） |
| 终止 | 倾角 > 1.2 rad 判定摔倒 |
| 控制台 | `pitch deg` / `roll deg` / `yaw deg` 三列（平均绝对值） |

### 5.6 附带说明：`error_vel_xy` 显示值为什么是真实值的 2 倍

命令项的误差指标每步累加 `误差 / (指令上限/dt)`，而**只在回合结束时清零**。
20 s 回合 = 1000 步，归一化分母是 500 步，所以：

```
显示值 = Σ(误差)/500 = 1000/500 × 平均误差 = 2 × 真实平均误差
```

**看到 0.05 就代表真实平均误差 0.025。**
